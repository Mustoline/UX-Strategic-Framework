# Evidence Ingest

Use this skill to turn mixed raw inputs into a structured evidence baseline for discovery work.

This skill is responsible for evidence handling, not final strategic recommendation. It should make the evidence clearer, separate signal from assumption, and show where the team still lacks confidence.

## What this skill should produce

For most requests, produce an evidence pack with:

* A source inventory
* A normalized summary of key signals from each source
* A known-versus-assumed view
* A short interpretation of where the strongest evidence sits
* A list of gaps, conflicts, and validation questions

## Operating modes

### Prep

Before reviewing the material, confirm:

* Which package and activity this evidence supports
* What decision or discovery question the evidence needs to inform
* Which sources are available and how recent they are
* Whether the evidence is quantitative, qualitative, or mixed
* Whether the team already suspects conflicts or weak coverage

If information is missing, make reasonable assumptions and state them.

### Run

While reviewing the evidence:

* Treat each source on its own terms before combining it with the others
* Separate direct evidence from interpretation
* Pull out repeated patterns, breakdowns, barriers, and decision signals
* Flag weak sample sizes, outdated material, or overconfident conclusions
* Highlight where sources reinforce each other and where they conflict
* Avoid turning one anecdote into a strategic conclusion

### Synthesize

After review:

* Normalize the evidence into a structure later skills can reuse
* Show what appears well supported versus what remains assumption
* Name the strongest signals, biggest evidence gaps, and the next questions to validate
* Keep outputs short, decision-oriented, and easy to scan

## Source handling

Use [source-patterns.md](references/source-patterns.md) to handle source types appropriately:

* Analytics
* Support issues
* Sales or commercial input
* Prior research
* Operational data
* Interview or observation notes

Do not force all sources into the same level of confidence. Some sources show scale, others show texture, and others reveal internal interpretation.

## Output templates

Use [evidence-templates.md](references/evidence-templates.md) for:

* Source inventory
* Evidence log
* Known-versus-assumed matrix
* Signal summary
* Evidence-gap list
* Evidence baseline summary

Adapt the template to the task rather than filling every section mechanically.

## Evidence rules

* Be explicit about what the evidence can and cannot support
* Name the source behind each major signal where practical
* Prefer pattern-level observations over transcript-like summaries
* Distinguish scale, frequency, severity, and business impact where possible
* If different sources conflict, preserve the conflict rather than smoothing it away
* If the evidence base is weak, say so directly and turn that into a validation priority

## Minimum output standard

Unless the user asks for something else, return these sections:

1. Evidence objective
2. Sources reviewed
3. Strongest signals
4. Known versus assumed
5. Conflicts or gaps
6. Questions to validate next

## Boundaries

This skill does not replace the activity-facing skill that uses the evidence. It prepares the evidence baseline so workshops, interviews, mapping, and recommendation work can start from a grounded shared view.
