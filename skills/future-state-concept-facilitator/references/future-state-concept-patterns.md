# Future-state concept patterns

Use this reference to structure the Package B future-state concept session.

## Concept objective

The purpose of the future-state concept session is to turn the current-state evidence into a practical target journey that stakeholders can review and later prioritize.

By the end of the session, the team should have enough clarity on:

* What the future-state journey needs to do differently
* Which experience principles should guide the concept
* Which changes are required behind the interface
* Which parts of the direction are ready for prototype and prioritization work
* Which questions or dependencies still need follow-up

## Recommended concept flow

### 1. Reconfirm the frame

Start by restating:

* The journey in scope
* The business case and outcomes this concept should support
* The main user needs, barriers, and decision criteria already identified

### 2. Define the future-state promise

Capture:

* What should feel easier, clearer, faster, or more trustworthy in the target journey
* Which user outcomes the concept should improve
* Which business or service outcomes the concept should support

### 3. Set the experience principles

Define:

* A small set of practical principles that describe how the concept should behave
* Principles that can guide later prototype and prioritization decisions

### 4. Map the future-state journey

Describe:

* The key future-state stages
* What users need to understand, decide, or complete at each stage
* Which touchpoints or service moments matter most

### 5. Add the service-change layer

List:

* Process changes required to support the concept
* Content changes required to make the journey understandable
* Ownership changes required to keep the service working
* Data changes required for the concept to function credibly

### 6. Close with implications and open checks

Summarize:

* Which parts of the concept are solid enough to carry forward
* Which assumptions, dependencies, or unresolved questions remain
* What the later prototype and prioritization work should focus on

## What the future-state journey must contain

At minimum, capture:

* Future-state journey stages
* User goals and key actions
* Important touchpoints or service moments
* The intended improvement at each stage
* The main service changes required behind the scenes

## Service-change framing

Use these four lenses:

* `Process`: What steps, approvals, or handoffs need to change?
* `Content`: What information, guidance, or messaging needs to change?
* `Ownership`: Which team or role needs clearer responsibility?
* `Data`: Which inputs, integrations, or information flows need to change?

Treat service changes as practical delivery implications, not a separate wish list.

## Common watchouts

* The session turns into free-form ideation instead of a bounded concept-definition exercise
* The future-state concept ignores the strongest current-state breakdowns
* The team focuses only on interface ideas and misses process or ownership changes
* Experience principles become vague slogans that cannot guide later choices
* The concept overreaches beyond the agreed journey in scope
* Open questions are hidden because the team wants a cleaner target-state story
