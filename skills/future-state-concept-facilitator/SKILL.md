# Future-State Concept Facilitator

Use this skill for Package B Activity `3.1`: the future-state concept work that turns the current-state evidence into a practical target journey and a clear view of what has to change behind the interface.

This skill should help the team define the future-state journey, agree the main experience principles, and identify the changes needed in process, content, ownership, or data so the concept can support delivery planning rather than staying at a screen-idea level.

This skill should build on the helper layer:

* Use [workshop-design-kit](../workshop-design-kit/SKILL.md) for agenda, facilitation structure, and playback logic
* Use [map-structure-generator](../map-structure-generator/SKILL.md) to shape the future-state journey scaffold and service-change structure
* Use [artifact-writer](../artifact-writer/SKILL.md) to draft the future-state readout cleanly
* Use [ux-strategy-reviewer](../ux-strategy-reviewer/SKILL.md) as the final quality check on client-facing outputs

It should also use the earlier Package B outputs where relevant:

* [scoping-workshop-facilitator](../scoping-workshop-facilitator/SKILL.md) for the journey in scope, business case, success measures, and discovery questions
* [user-research-runner](../user-research-runner/SKILL.md) for the top user needs, barriers, and decision points
* [current-journey-synthesizer](../current-journey-synthesizer/SKILL.md) for the main breakdowns, opportunity areas, and decision criteria

## What this skill should produce

For most requests, produce a concept-definition pack with:

* A concept objective tied to the journey in scope and the decisions ahead
* A timed agenda for a 2-3 hour concept working session
* A short set of experience principles for the future-state concept
* A future-state journey structure that shows how the experience should work end to end
* A service-change view across process, content, ownership, and data
* A short concept readout with implications, open questions, and next checks

## Operating modes

### Prep

Before the concept session, confirm:

* Which journey or service area is in scope
* Which current-state findings and opportunity areas matter most
* Which user needs and decision criteria the concept must respond to
* Which stakeholders need to participate to define the service changes credibly
* Which delivery questions the concept work must make easier

Then:

* Use `workshop-design-kit` to shape the 2-3 hour session
* Use `map-structure-generator` to prepare the future-state journey scaffold
* Use the flow in [future-state-concept-patterns.md](references/future-state-concept-patterns.md)
* Prepare the output structure in [future-state-concept-templates.md](references/future-state-concept-templates.md)

### Run

During the concept session:

* Keep the discussion tied to the selected journey and the opportunity areas already agreed
* Start from the user needs and decision criteria rather than jumping straight to features
* Push the group to describe how the future-state journey should work end to end
* Surface what needs to change in process, content, ownership, and data for the concept to work in practice
* Distinguish the target concept from detailed delivery design
* End with a short playback of the future-state journey, the main service changes, and the open questions

### Synthesize

After the concept session:

* Produce a concise future-state journey summary
* Capture the experience principles and service changes clearly
* Show what the concept implies for delivery planning and prioritization
* Preserve assumptions, dependencies, and unresolved questions rather than smoothing them over
* If needed, hand the draft to `artifact-writer` and then to `ux-strategy-reviewer`

## Core concept objectives

The future-state concept work should answer:

* What should the selected journey feel and function like in the future state?
* Which experience principles should guide the concept?
* Which changes in process, content, ownership, or data are required to support it?
* Which parts of the concept are clear enough to carry into prioritization and prototyping?
* Which questions, dependencies, or assumptions still need validation?

## Facilitation rules

* Treat the concept session as a future-state decision exercise, not a generic ideation workshop
* Keep the concept anchored in evidence from the scoping, interview, and current-state work
* Show how the journey should change across the full flow, not only at one visible touchpoint
* Make supporting service changes explicit so the concept does not overpromise
* Use principles and future-state steps to clarify the direction, not to create abstract slogans
* If the group cannot settle a point confidently, capture it as an open question or validation need

## Minimum output standard

Unless the user asks for something else, return these sections:

1. Concept objective
2. Suggested 2-3 hour agenda
3. Experience principles
4. Future-state journey
5. Required service changes
6. Open questions, dependencies, and next checks

## Boundaries

This skill covers Activity `B3.1` only. It defines the future-state concept and the service changes it depends on. It does not replace the later prototype-building or prioritization work.
