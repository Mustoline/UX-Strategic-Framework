# Ecosystem Workshop Facilitator

Use this skill for Package C Activity `1.2`: the half-day ecosystem workshop that turns the strategic interview framing into an agreed service scope and study focus.

This skill should help the team identify the departments, touchpoints, systems, and operational actors shaping the experience, define where to focus the work, and name the critical service moments the later fieldwork and blueprinting should examine.

This skill should build on the helper layer:

* Use [workshop-design-kit](../workshop-design-kit/SKILL.md) for agenda, facilitation structure, and playback logic
* Use [map-structure-generator](../map-structure-generator/SKILL.md) to shape the ecosystem-map scaffold, labels, and study-focus structure
* Use [artifact-writer](../artifact-writer/SKILL.md) to draft the workshop output cleanly
* Use [ux-strategy-reviewer](../ux-strategy-reviewer/SKILL.md) as the final quality check on client-facing outputs

It should also use earlier Package C outputs where relevant:

* [executive-and-service-owner-interviewer](../executive-and-service-owner-interviewer/SKILL.md) for the business case, strategic priorities, service pressures, and investment questions
* Use [evidence-ingest](../evidence-ingest/SKILL.md) if existing service or operational inputs need to be normalized before or after the workshop

## What this skill should produce

For most requests, produce an ecosystem workshop pack with:

* A workshop objective tied to the service problem and the decisions ahead
* A timed agenda for a half-day session
* Critical questions and prompts for mapping the service ecosystem
* A note structure focused on departments, touchpoints, systems, operational actors, and service boundaries
* An ecosystem map or structured equivalent
* A workshop summary showing the agreed service scope, critical service moments, and study focus for the next Package C steps

## Operating modes

### Prep

Before the workshop, confirm:

* Which service, proposition, or cross-functional initiative is in scope
* Which departments, channels, systems, or operational actors are already known to matter
* Which strategic themes, risks, or investment questions should shape the mapping
* Who needs to participate to define the service boundary credibly
* Which later fieldwork or blueprint decisions this workshop must make easier

Then:

* Use `workshop-design-kit` to shape the half-day ecosystem session
* Use `map-structure-generator` to prepare the ecosystem-map scaffold
* Use the patterns in [ecosystem-workshop-patterns.md](references/ecosystem-workshop-patterns.md)
* Prepare the output structure in [ecosystem-workshop-templates.md](references/ecosystem-workshop-templates.md)

### Run

During the workshop:

* Keep the discussion tied to the service, not only to one team, channel, or interface
* Map departments, touchpoints, systems, and operational actors that shape the experience
* Push the group to define the service boundary and what sits outside it
* Surface where handoffs, dependencies, or ownership gaps are likely to matter most
* Name the critical service moments the later study should follow
* End with a short playback of the agreed scope, main ecosystem dependencies, and study focus

### Synthesize

After the workshop:

* Draft a concise ecosystem workshop summary
* Capture the agreed service scope, ecosystem structure, and critical service moments clearly
* Show what the later fieldwork and service-blueprint work should examine next
* Preserve disagreements, gaps, or unresolved scope issues rather than smoothing them away
* If needed, hand the draft to `artifact-writer` and then to `ux-strategy-reviewer`

## Core workshop objectives

The ecosystem workshop should answer:

* Which departments, touchpoints, systems, and operational actors shape the service experience?
* Where should the study place its boundary so the work stays focused but still meaningful?
* Which service moments are most critical to understand in later fieldwork?
* Where are the biggest dependencies, handoffs, or ownership questions likely to sit?
* What should the later current-state blueprint work make visible?

## Facilitation rules

* Treat the workshop as a service-scope alignment session, not a general stakeholder meeting
* Keep the conversation at service and operating-model level, not only at feature or interface level
* Ask where value is lost, effort is added, or ownership becomes unclear across the ecosystem
* Make in-scope and out-of-scope areas explicit so later fieldwork stays usable
* If the group cannot define a clean boundary, document the tension rather than forcing false clarity
* Prefer a workable study focus over an exhaustive model of the whole organization

## Minimum output standard

Unless the user asks for something else, return these sections:

1. Workshop objective
2. Suggested half-day agenda
3. Critical ecosystem questions
4. Note structure
5. Ecosystem map and service-scope summary
6. Critical service moments, study focus, and open risks

## Boundaries

This skill covers Activity `C1.2` only. It aligns the service scope and ecosystem for Package C. It does not replace the later fieldwork, current-state blueprinting, future-state service model, validation, or roadmap work.
