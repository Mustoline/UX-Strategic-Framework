# Prototype and prioritization patterns

Use this reference to structure the Package B prototype and prioritization step.

## Contents

* Objective
* Recommended flow
* What the prototype brief must contain

## Objective

The purpose of this step is to make the future-state concept tangible enough for stakeholder review and turn it into a practical delivery recommendation.

By the end of the work, the team should have enough clarity on:

* Which core flow the clickable prototype needs to show
* Which user and business questions the prototype should help clarify
* Which opportunities should be built first
* Which items should be deferred or validated before delivery
* Which dependencies or constraints affect sequencing

## Recommended flow

### 1. Reconfirm the concept and decision frame

Start by restating:

* The journey in scope
* The future-state concept being carried forward
* The delivery or prioritization decision this step must support

### 2. Define the prototype scope

Capture:

* Which stages or moments of the core flow the prototype must include
* Which assumptions or questions the prototype should make easier to review
* What is deliberately out of scope for this prototype

### 3. Translate the concept into a clickable core-flow brief

Describe:

* The key screens, service moments, or transitions to illustrate
* What the user needs to understand, decide, or complete at each moment
* Which concept principles or service changes the prototype needs to reflect

### 4. Set the prioritization criteria

Use these primary lenses:

* User value
* Business relevance
* Implementation effort

Add dependencies or validation needs where they materially affect the order.

### 5. Rank opportunities and shape the sequence

Clarify:

* Which items belong in the first delivery move
* Which items should be deferred
* Which items require more validation before commitment

### 6. Close with a delivery-facing recommendation

Summarize:

* What should be built first and why
* What should wait
* What still needs checking before scope is locked

## What the prototype brief must contain

At minimum, capture:

* The purpose of the clickable prototype
* The core flow or key moments to include
* The user groups in focus
* The questions the prototype should help stakeholders review
* What is out of scope for the prototype

## Prioritization framing

The final recommendation should:

* Show how user value and business relevance balance against effort
* Treat implementation effort as a sequencing input, not a reason to ignore important user problems
* Make deferred and validation items explicit
* Stay close enough to the concept and evidence that the result can guide the next delivery step

## Common watchouts

* The prototype scope becomes too broad to be useful
* The prototype is treated like a polished final design rather than a concept review tool
* Prioritization becomes a politics exercise instead of a criteria-based decision
* Delivery effort dominates the discussion so strongly that user value disappears
* Deferred items are hidden rather than named
* The final recommendation does not make the next step clear
