# Prototype And Prioritization Facilitator

Use this skill for Package B Activity `4.1`: the final Package B step that makes the concept tangible and turns it into a practical delivery recommendation.

This skill should help the team define what the clickable prototype must show, use that prototype view to review the proposed direction, and rank opportunities based on user value, business relevance, and implementation effort so the client can see what to build first, what to defer, and what to validate next.

This skill should build on the helper layer:

* Use [workshop-design-kit](../workshop-design-kit/SKILL.md) for agenda, facilitation structure, and playback logic
* Use [artifact-writer](../artifact-writer/SKILL.md) to draft the prototype brief and prioritization output cleanly
* Use [ux-strategy-reviewer](../ux-strategy-reviewer/SKILL.md) as the final quality check on client-facing outputs

It should also use the earlier Package B outputs where relevant:

* [scoping-workshop-facilitator](../scoping-workshop-facilitator/SKILL.md) for the journey in scope, business case, and success measures
* [user-research-runner](../user-research-runner/SKILL.md) for the top user needs, barriers, and decision criteria
* [current-journey-synthesizer](../current-journey-synthesizer/SKILL.md) for the current-state breakdowns and opportunity areas
* [future-state-concept-facilitator](../future-state-concept-facilitator/SKILL.md) for the target journey, experience principles, and required service changes

## What this skill should produce

For most requests, produce a prototype-and-prioritization pack with:

* A prototype objective tied to the decision the client now needs to make
* A clickable core-flow brief showing which moments the prototype must make tangible
* A timed agenda for a 2-hour prioritization workshop
* A prioritization matrix using user value, business relevance, and implementation effort
* A build-first recommendation with defer and validate-next items
* A concise delivery-facing summary of risks, dependencies, and next steps

## Operating modes

### Prep

Before the prototype and prioritization step, confirm:

* Which future-state journey or concept is being made tangible
* Which key moments or decisions the prototype must illustrate
* Which opportunities, changes, or concept elements need prioritization
* Which effort signals, delivery constraints, or dependencies are already known
* Which stakeholders need to take part in the prioritization decision

Then:

* Use `workshop-design-kit` to shape the 2-hour prioritization workshop
* Use the flow in [prototype-and-prioritization-patterns.md](references/prototype-and-prioritization-patterns.md)
* Prepare the prototype brief and prioritization structure in [prototype-and-prioritization-templates.md](references/prototype-and-prioritization-templates.md)

### Run

During the prototype and prioritization step:

* Keep the prototype scope focused on the core flow and key decision points
* Use the future-state concept as the basis rather than redesigning the concept from scratch
* Treat the prototype as a review and decision aid, not a polished final design
* Compare opportunities against the same criteria rather than personal preference
* Make service dependencies and implementation implications visible alongside user and business value
* End with a clear playback of what should be built first, what should wait, and what still needs validation

### Synthesize

After the workshop:

* Produce a concise prototype brief for the core flow
* Capture the prioritization logic and the ranked recommendation clearly
* Show what the team should build first, defer, or validate next
* Highlight the main risks, dependencies, and sequencing implications for delivery
* If needed, hand the draft to `artifact-writer` and then to `ux-strategy-reviewer`

## Core objectives

The prototype and prioritization work should answer:

* Which parts of the future-state concept need to be made tangible first?
* Which moments should the clickable prototype include?
* Which opportunities or changes should be built first, deferred, or validated next?
* How do user value, business relevance, and implementation effort affect the delivery sequence?
* Which risks, dependencies, or unknowns still matter before delivery scope is locked?

## Facilitation rules

* Keep the prototype scope tight enough to support a real decision
* Use the prototype to clarify the concept, not to create a full product specification
* Rank opportunities against agreed criteria, not stakeholder seniority
* Keep user value, business relevance, and implementation effort in view at the same time
* Make it explicit when an item is deferred because of effort, dependency, or uncertainty
* Prefer a practical first-step recommendation over a false sense of precision

## Minimum output standard

Unless the user asks for something else, return these sections:

1. Prototype objective
2. Clickable core-flow brief
3. Suggested 2-hour prioritization agenda
4. Prioritization matrix
5. Build first, defer, and validate next
6. Risks, dependencies, and next steps

## Boundaries

This skill covers Activity `B4.1` only. It defines the prototype scope and prioritization recommendation for Package B. It does not replace detailed interaction design, technical specification, or delivery planning.
