# Skills Library

This folder contains the internal skill library that supports the strategic UX and service design package system.

These skills are not client-facing deliverables. They are internal execution helpers used to support workshops, evidence synthesis, mapping, concept definition, recommendation writing, and quality review behind the package flow.

For the activity-by-activity package mapping, see [../Packages/English/internal_activity_skill_mapping.md](../Packages/English/internal_activity_skill_mapping.md).

## How To Read This Library

The skills fall into four groups:

* **Shared helper skills** used across multiple packages
* **Package A skills** for the Discovery sprint
* **Package B skills** for Service concept definition
* **Package C skills** for Strategic service redesign

## Shared Helper Skills

| Skill | Purpose |
| --- | --- |
| `artifact-writer` | Drafts clear client-facing or internal discovery artifacts from validated workshop, research, mapping, or strategy output. |
| `discovery-interview` | Provides deeper guided clarification when a brief, intake, or decision area is still too vague or underspecified. |
| `evidence-ingest` | Normalizes mixed evidence sources so later synthesis work starts from a cleaner and more structured baseline. |
| `map-structure-generator` | Creates reusable scaffolds, labels, and logic for journey maps, ecosystem maps, and service blueprints. |
| `ux-strategy-reviewer` | Reviews strategy documents for business clarity, Danish-pragmatic tone, ROI logic, and markdown quality. |
| `workshop-design-kit` | Supplies reusable workshop structure, facilitation logic, and note-capture support across package activities. |

## Package A Skills

Package A is the **Discovery sprint** for a bounded problem that needs a fast but grounded delivery decision.

| Skill | Purpose |
| --- | --- |
| `sponsor-workshop-facilitator` | Frames the sprint by aligning decision-makers on the business question, target users, success criteria, and constraints. |
| `evidence-baseline-reviewer` | Reviews existing evidence so the sprint starts from known signals rather than assumption or internal debate. |
| `journey-step-mapper` | Maps one selected journey step to expose where users or staff lose time, confidence, or momentum. |
| `option-review-facilitator` | Compares 1-2 solution directions against agreed business, user, and delivery criteria. |
| `recommendation-packager` | Packages the final sprint recommendation into a concise decision-ready document and concept brief. |

## Package B Skills

Package B is **Service concept definition** for shaping the right concept, journey, and service changes before delivery scope is locked.

| Skill | Purpose |
| --- | --- |
| `scoping-workshop-facilitator` | Aligns the sponsor and key stakeholders on the journey in scope, business case, success measures, and discovery questions. |
| `user-research-runner` | Plans and runs the Package B interview stream to clarify user needs, barriers, and decision criteria. |
| `current-journey-synthesizer` | Turns interview evidence and service context into a current-state journey view with clear breakdowns and opportunity areas. |
| `future-state-concept-facilitator` | Defines the target journey and the required changes in process, content, ownership, and data. |
| `prototype-and-prioritization-facilitator` | Turns the concept into a clickable core-flow brief and a prioritized delivery recommendation. |

## Package C Skills

Package C is **Strategic service redesign** for broader service and operating-model change across teams, channels, or systems.

| Skill | Purpose |
| --- | --- |
| `executive-and-service-owner-interviewer` | Runs the strategic interview stream that clarifies the business case, service pressures, and investment questions. |
| `ecosystem-workshop-facilitator` | Aligns stakeholders on the service scope across departments, touchpoints, systems, and operational actors. |
| `contextual-fieldwork-runner` | Plans and runs contextual interviews, observations, or shadowing to reveal how the service works in practice. |
| `service-blueprint-builder` | Builds the current-state service blueprint that exposes delays, duplication, cost, and ownership gaps. |
| `future-state-service-model-and-validation` | Defines the target-state service model and validates it with relevant users, customers, or internal stakeholders. |
| `roadmap-and-business-case-framer` | Turns the validated target-state model into a phased roadmap, change implications, and an ROI hypothesis. |
