# Workshop Design Kit

Use this skill to create the reusable scaffolding for discovery workshops across Package A, Package B, and Package C.

This skill is responsible for structure, facilitation logic, and outputs. It should not invent business conclusions that are not supported by the available evidence.

## What this skill should produce

For most workshop requests, produce a workshop pack with:

* A clear workshop objective tied to a business decision or discovery question
* A timed agenda with named segments
* A facilitation guide with critical prompts and follow-up probes
* A note-capture structure aligned to the intended output
* A playback summary structure with decisions, assumptions, risks, and next steps

## Operating modes

### Prep

Before designing the workshop, confirm:

* Which package and activity this supports
* What decision, alignment point, or artifact the session must support
* Duration and participant roles
* What evidence, constraints, or known disagreements already exist
* What the team needs to leave the room with

If key information is missing, make reasonable assumptions and state them.

### Run

While supporting a live session:

* Keep the discussion tied to the decision the workshop must support
* Separate facts, assumptions, preferences, and constraints
* Push for concrete wording rather than abstract ambition
* Surface unresolved disagreements clearly
* Timebox divergence and convergence
* End each major section with a short playback of what was agreed

### Synthesize

After the session:

* Convert notes into a concise playback summary
* Highlight decisions made, assumptions still open, risks, dependencies, and next steps
* Format the outputs so an activity-facing skill or reviewer can use them directly

## Pattern selection

Choose the workshop pattern that best matches the task:

* Sponsor or scoping session: Use the alignment and decision pattern
* Journey-step or current-state mapping: Use the mapping pattern
* Option review or prioritization: Use the comparison and prioritization pattern
* Future-state concept session: Use the concept definition pattern
* Ecosystem workshop: Use the ecosystem alignment pattern
* Roadmap or business case session: Use the sequencing and change pattern

Read [workshop-patterns.md](references/workshop-patterns.md) to select the right structure.

## Output templates

Use [workshop-templates.md](references/workshop-templates.md) for:

* Agenda structure
* Note-capture grid
* Decision log
* Assumption and constraint register
* Playback summary

Adapt the template to the session rather than copying it mechanically.

## Facilitation rules

* Frame every workshop around a practical business question, not a general discussion
* Make participant roles explicit so decisions do not disappear into group ambiguity
* Keep workshop outputs tangible and decision-oriented
* Name what is out of scope if the conversation starts to widen
* If the group lacks enough evidence to decide, say so clearly and turn that into a next-step question
* Prefer short, readable outputs over exhaustive transcripts

## Minimum output standard

Unless the user asks for something else, return these sections:

1. Workshop objective
2. Suggested agenda
3. Facilitation prompts
4. Note structure
5. Playback summary template
6. Risks or watchouts

## Boundaries

This skill does not replace the domain-specific skill for the activity itself. It provides the workshop operating system: structure, prompts, timeboxes, and output logic.
