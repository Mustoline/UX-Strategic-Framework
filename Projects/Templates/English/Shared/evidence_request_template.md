# Evidence request template

## Purpose

Use this template when a live Package A, Package B, or Package C activity depends on evidence, access, exports, or background material from the client team.

The goal is to request the strongest relevant inputs without creating unnecessary admin work or asking for a perfect research pack before the activity can move.

## When to use it

Use this template when you need any of the following:

* analytics or performance data
* support themes or complaint patterns
* sales or commercial input
* prior research or usability findings
* session recordings, heatmaps, dashboards, or raw exports
* access to users, customers, frontline teams, or internal roles
* permission for observation, shadowing, or interviews

## Required structure

Use this order in the message:

1. `Why we are asking`
2. `Decision or activity this supports`
3. `What would be most useful`
4. `What format is acceptable`
5. `What to call out if missing`
6. `Timing`
7. `Thanks and next step`

## Core drafting rules

* Keep the request short, practical, and specific
* Ask for the strongest available evidence, not every possible source
* Make it clear that raw exports, screenshots, notes, or dashboards are acceptable
* Ask the recipient to flag missing segmentation or unavailable access directly
* Keep the request bounded to the package scope

## Package-specific adaptation notes

### Package A

Use for:

* journey-step analytics
* conversion or drop-off data
* segmentation by device, source, customer type, or basket size
* support or complaint themes for the selected step
* prior research or behavior evidence tied to the selected breakdown

Emphasize:

* the near-term decision to support
* the selected step in scope
* the need to distinguish supported signals from assumptions

### Package B

Use for:

* current journey performance signals
* prior research, customer feedback, support themes, or sales input
* recruitment support for interviews
* access to the relevant user groups
* any constraints affecting outreach, consent, or confidentiality

Emphasize:

* understanding user needs, barriers, and decision points
* getting enough evidence to shape interview focus and later concept work
* requesting access as well as evidence

### Package C

Use for:

* operational data and service performance signals
* support case types or service volume data
* documentation of current process, ownership, or system dependencies
* access to frontline teams, internal roles, users, or customers
* permission for observation or shadowing

Emphasize:

* real service behavior in practice
* cross-team and cross-system implications
* access to people and operational reality, not only reports

Hi,

### Why we are asking
[One or two sentences explaining the immediate purpose.]

### Decision or activity this supports
[State the activity or decision in plain language.]

### What would be most useful
* [Evidence, access, or material]
* [Evidence, access, or material]
* [Evidence, access, or material]

### What format is acceptable
Raw exports, screenshots, dashboards, notes, links, or short summaries are all fine at this stage. We do not need perfect documentation.

### What to call out if missing
If something is not available, please note that directly, especially if segmentation, access, or permissions are missing.

### Timing
[State when the material is ideally needed.]

### Thanks and next step
Thank you. Once we have the strongest available inputs, we will use them to support the next stage of the package.
